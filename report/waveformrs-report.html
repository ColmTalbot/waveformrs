Summary

The crate started with two models, TaylorF2 and IMRPhenomD. It had no tests, and both models disagreed with LALSimulation by mismatches of up to 0.14. Both now agree with LALSimulation at rounding level and run about twice as fast as before. Eight more model configurations were ported, ending with IMRPhenomXPHM using the numerical SpinTaylor precession angles, followed by the time-domain NR surrogate NRSur7dq4. Every model is checked against LALSimulation by cargo test and by 2,200 random parameter draws. For samplers, which evaluate many waveforms on one frequency grid, a grid path removes the remaining per-frequency transcendental functions.

The four tasks and their outcomes:

  • Assessment. Section 2 describes the crate as found. The defects that separated it from LALSimulation are listed in section 3.
  • Testing against LALSimulation. Every model, including each precession-angle option and each fallback path, has reference data from LALSimulation in tests/data. A harness compares the models over random draws (section 4, section 5).
  • Optimisation. Every model runs faster than LALSimulation on one thread, without changing the existing API (section 6). Section 12 lists API changes that would give more.
  • IMRPhenomXPHM with SpinTaylor angles. This is implemented, together with the models and integrator it builds on (section 8, section 9). The SpinTaylor Euler angles agree with LALSimulation's bit for bit, and the polarizations agree to ≲ 1e-15.

LALSimulation bug found along the way. In multi-threaded builds, IMRPhenomXP's default MSA angles and its PNR angles are wrong at some frequencies, and the output changes from run to run. Errors reach several percent of the peak amplitude, and are of order one for PNR. The cause is a data race on IMRPhenomXPrecessionStruct inside an OpenMP loop. Section 11 summarises it. The full write-up with the lines to fix is report/lalsimulation-openmp-race.md.

The crate as found

On main (87f9d9b, a single commit) the crate had about 1,600 lines of Rust in 13 files:

  • A Waveform trait with orbital_speed, phase and amplitude, plus default waveform_single_frequency, waveform and waveform_modes methods. The last one returns h+ and h× for an inclination.
  • TaylorF2: post-Newtonian phasing up to 3.5PN with spin-orbit, spin-spin and tidal terms, and PN amplitude corrections (src/pn.rs, src/taylor.rs).
  • IMRPhenomD: the phenomenological inspiral–merger–ringdown model, with its amplitude collocation system solved by LAPACK through ndarray-linalg (src/imrphenomd/).
  • Dependencies: ndarray, ndarray-linalg and blas-src (Accelerate), with macOS-specific link flags in .cargo/config.toml. autodiff was listed but unused.
  • Tests: none, and no reference data or comparison against LALSimulation. Two examples printed timings.

To measure where it stood, I compared the original code with LALSimulation on 100 random aligned-spin binaries per model. The match is maximised over time and phase, so differing phase conventions don't count against it. The mismatch is weighted by the aLIGO design sensitivity.

How the models are tested

Reference data in cargo test

scripts/generate_reference_data.py calls lalsimulation and stores waveforms as JSON in tests/data; serde_json is built with float_roundtrip so no bits are lost. The waveforms come from SimInspiralChooseFDWaveformSequence on non-uniform grids and SimInspiralChooseFDWaveform on uniform grids, for both polarizations. Individual higher modes come from SimIMRPhenomXHMFrequencySequenceOneMode, Euler angles from SimIMRPhenomXPSpinTaylorAngles, and orbits from SimInspiralSpinTaylorT4. The cases are chosen to cover:

  • equal and extreme mass ratios, down to 1/120 for the higher modes;
  • spins up to 0.95;
  • a 1.6 + 1.3 M☉ binary, whose inspiral phase reaches ~106 rad;
  • heavy binaries that trigger LAL's fallbacks;
  • non-default reference frequencies, uniform grids and restricted mode arrays.

The integration tests in tests/lalsimulation.rs and tests/spintaylor.rs require a relative error ≤ 1e-10 (TaylorF2, IMRPhenomD) or ≤ 1e-9 (IMRPhenomX family), and a mismatch ≤ 1e-14 or ≤ 1e-12. In practice the errors are far below these limits:

Random draws

scripts/validate_against_lalsimulation.py draws 200 binaries per model and evaluates both codes on the same uniform grid. Rust is driven through examples/lal_validation.rs, which reads JSON on stdin.

  • Parameters: M log-uniform in [5, 300] M☉; q uniform in [1/20, 1] (1/18 for IMRPhenomD); aligned spins uniform in ±0.99, or isotropic spin vectors with |χ| ≤ 0.99 for the precessing models.
  • Frequencies: fmin ∈ {10, 15, 20} Hz; fref = fmin, or uniform in [fmin, 3 fmin]; Δf = 0.25 Hz up to the model's cutoff or 2048 Hz.
  • Extrinsic: isotropic inclination; uniform reference phase; distance log-uniform in [100, 3000] Mpc.

Each draw records three things:

  • the largest relative error;
  • the noise-weighted mismatch (aLIGO zero-detuned high-power PSD), with no maximisation over time or phase, so a constant phase offset would show up;
  • the median time of five calls for each code.

When LALSimulation silently changes method, the harness records the case separately and compares it against the method LAL fell back to, as in the SpinTaylor → MSA case (section 11). In the final run every draw was compared directly.

Agreement to the last bit

Matching to ~1e-9 needs the same formulas. For three components, matching better than that needs the same floating-point operations:

  • The SpinTaylor integrator. Its adaptive step-size control turns last-bit differences in the derivatives into different accepted steps, and those grow to ~1e-7 in the spins.
  • The IMRPhenomXHM (3,2) mode. Its intermediate phase uses a finite-difference second derivative with a step of 1e-7, which amplifies rounding by ~1014. Even LALSimulation's own (3,2) mode changes by up to 3e-3 when the inputs move by 1e-15.
  • The cubic splines and final-state fits that set the ringdown frequencies, and through them the SpinTaylor time step.

On Apple silicon, clang compiles LALSimulation and GSL with -ffp-contract=on. It fuses a*b + c into a single-rounding fused multiply-add wherever the product and the sum appear in the same expression, and OpenBLAS (behind GSL's LU solves) fuses as well. src/spintaylor/fp.rs provides fma, fms and fnms helpers that reproduce clang's contraction rule, and the ported code uses them operation by operation. The parameter-space fits of IMRPhenomXAS and XHM were generated from the C sources with the same rule. With this the SpinTaylor orbit, the splines, the remnant fits, every IMRPhenomX/XHM coefficient and the SpinTaylor and MSA Euler angles are bit-identical to LALSimulation on this platform.

On x86-64, builds without hardware FMA don't contract, and the helpers fall back to separate rounding. That configuration hasn't been tested (section 13).

Threads

All LALSimulation runs use OMP_NUM_THREADS=1. Besides giving fair single-core timings, this is needed because multi-threaded IMRPhenomXP is not deterministic with the MSA angles (section 11).

Performance

What was changed

  • One set of transcendental calls per frequency. TaylorF2 and IMRPhenomD now compute the shared powers of v or Mf once per frequency: one cbrt, one ln and one sin_cos. Amplitude and phase both use them, and nothing is evaluated twice through the trait's separate phase/amplitude methods (5f426f9).
  • Polynomial evaluation. The PN phase polynomials use Estrin's scheme instead of Horner's. TaylorF2 has a fast path for point-particle phasing and falls back to a sparse Horner evaluation when tidal terms are present (d44fb0f). powf and powi were removed from hot loops.
  • No LAPACK. The IMRPhenomD amplitude collocation uses a fixed-size Gaussian elimination, and the IMRPhenomX collocation systems use a port of GSL's LU solve. The setup costs 0.4–1 µs per waveform.
  • Buffer reuse. The default waveform_modes builds h+ in place in the waveform buffer instead of allocating three vectors.
  • Precessing models.
    • Euler angles and twisting factors (eikα, powers of the half angles, the ε phase) are computed once per frequency and per m′, and shared by all modes with that m′.
    • No allocation happens per mode or per frequency.
    • The SpinTaylor γ integration stops 64 knots past the last frequency it is needed for, and repeated Boole-rule sums are cached. The output is bit-identical.
    • The degenerate MSA case skips the spin-magnitude cubic.
  • Whole-program optimisation. Adding the IMRPhenomXHM modules changed LLVM's inlining decisions and slowed IMRPhenomXAS from 112 to 151 µs, even though the XAS code was unchanged. A single codegen unit doesn't recover it; fat LTO does, bringing it to ~105 µs. The release profile now sets lto = "fat" (3719da8). Crates that depend on waveformrs should do the same.

Where the time goes in the precessing models

For IMRPhenomXPHM with SpinTaylor angles on the benchmark grid (about 4 ms):

  • the PN integration with the ported RKF45 integrator takes about 0.6 ms;
  • the γ grid (minimal-rotation integral) takes about 1.2 ms;
  • the five co-precessing modes take about 0.9 ms;
  • angles and twist factors at four values of m′ take about 1.0 ms;
  • twisting the modes up takes about 0.3 ms.

The MSA angles cost about 15 transcendental functions per frequency. These include a Jacobi elliptic function, ported from GSL's gsl_sf_elljac_e with its descending Landen transformation, and they are evaluated once per m′. MSA is therefore the slowest precessing variant in Rust, and the one with the smallest speed-up over LAL. All of these steps are bit-exact ports; changing their arithmetic would trade agreement with LAL for speed.

Many waveforms in sequence

A stochastic sampler evaluates one waveform after another, each with new parameters, on the same frequency grid. Two kinds of work can then be done once rather than for every waveform: the part of each transcendental function that depends only on the frequency, and the allocation of the output.

The grid path

Every frequency-domain model depends on the frequency only through a scaled frequency s·f, for example Mf or πMf. So its cube root, logarithm and inverse factorise: cbrt(s f) = cbrt(s)·cbrt(f) and ln(s f) = ln s + ln f.

  • FrequencyGrid::new(&frequencies) stores f1/3, f1/6, 1/f, ln f and f−7/6 once.
  • Each waveform then computes those functions once for its own scale s, and only multiplies at each frequency.
  • The new methods write into buffers the caller owns, so nothing is allocated per call: Waveform::waveform_on_grid, Waveform::waveform_modes_on_grid, IMRPhenomXHM::polarizations_on_grid, and the same for IMRPhenomXP and XPHM.
use waveformrs::{grid::FrequencyGrid, imrphenomx::IMRPhenomXAS, waveform::Waveform};

let grid = FrequencyGrid::uniform(20.0, 1024.0, 0.125);           // once
let mut hp = vec![Complex64::default(); grid.len()];
let mut hc = vec![Complex64::default(); grid.len()];
for p in &samples {                                               // many times
    IMRPhenomXAS::new(p.total_mass, p.mass_ratio, p.chi_1, p.chi_2, p.distance)
        .with_reference_frequency(20.0)
        .waveform_modes_on_grid(&grid, 2.0 * p.phi_ref, p.inclination, &mut hp, &mut hc);
    // ... likelihood ...
}

Once the powers come from the grid, sin_cos of the phase is the largest remaining cost, so the grid paths work in two passes:

  1. compute every amplitude and phase;
  2. convert them to complex values with an inlined sin_cos, which the compiler vectorises with NEON.

This sin_cos uses Cody–Waite reduction with fused multiply-adds and the fdlibm kernel polynomials, and stays within 3 ulp of the C library. A vectorised exp, within 3 ulp of libm, handles the SpinTaylor merger–ringdown angles and the γ integral. The grid paths agree with the per-frequency paths to ~1e-13 (tests/grid.rs). The per-frequency paths are unchanged, so they still match LALSimulation at rounding level.

Memory layout turned out to matter. When the five power arrays of a grid landed a whole number of pages apart, they competed for the same cache sets. The same benchmark binary then took 92 or 197 µs for IMRPhenomXAS, and 113 or 345 µs for IMRPhenomD, depending only on where the allocator put the arrays. FrequencyGrid now stores them in one allocation with staggered offsets, which keeps the timings stable.

What limits the gains

  • TaylorF2. On the grid, each frequency costs one polynomial and the vectorised sin_cos, about 6 ns. Its per-call time depends noticeably on memory layout. It includes allocating the outputs, and it slows down when the allocator places them in a way that conflicts in the cache with the input. A call takes about 150 µs for a single repeated binary, but averaged more than that over these 300 draws, roughly level with LAL. The grid path writes into fixed buffers and avoids this.
  • IMRPhenomD, XAS and XHM. Most of a 20–1024 Hz grid lies in the merger–ringdown region of a binary black hole, where each frequency still calls atan and exp. IMRPhenomXHM adds per-mode work. Its (3,2) ringdown is a sum of a spheroidal term and a rotated (2,2) term. The per-frequency path combines them with cexp and then splits the result back into amplitude and phase with atan2 and hypot. The grid path converts the two terms separately, which removes those calls.
  • IMRPhenomXP and XPHM. Their grid paths are 1.6×–3.5× faster than the per-call paths. They work in passes over the grid. The Euler angles are computed for each m′, the NNLO angles from the stored powers without transcendental functions, and the MSA angles in blocks of 32 frequencies. An MSA angle already computed for another m′ at a bit-identical argument is reused, which skips 29% of the evaluations for IMRPhenomXPHM. The ε phase is folded into each mode's phase before one vectorised conversion, and the twist-up keeps its sums in registers. What remains is the MSA angles, whose spin-cubic roots and corrections must use the C library to stay stable for nearly aligned spins; the SpinTaylor PN integration, about 0.5 ms; and the IMRPhenomXHM mode evaluations.
  • NRSur7dq4. It has no frequency grid. Reusing a workspace removes the allocations. The workspace also keeps the last binary's inertial-frame modes. When only inclination, phase, distance or Δt change, the surrogate is skipped and a waveform costs 0.03–0.15 ms instead of about 1 ms.

Larger levers

Past these constant factors, the biggest gains for a sampler come from evaluating fewer frequencies:

  • LAL's multibanding, not yet ported;
  • relative binning, or heterodyned likelihoods, which need a few hundred frequencies instead of thousands.

Caching the waveform across changes of the extrinsic parameters, as NRSur7dq4 now does, would also help the frequency-domain precessing models. Finally, the per-frequency loops are independent, so batches of waveforms could be spread over threads.

IMRPhenomXPHM needs IMRPhenomXAS for the (2,2) mode, IMRPhenomXHM for the other co-precessing modes, the SpinTaylorT4 equations with LAL's GSL integrator for the angles, and IMRPhenomXP's precession set-up. Each was ported and tested on its own before the next was built on it.

Precession-angle versions and fallbacks

PrecessionVersion selects LAL's PhenomXPrecVersion:

  • Nnlo (102): next-to-next-to-leading-order PN angles.
  • Msa (223): the multiple-scale-analysis angles of Chatziioannou et al. (2017).
  • SpinTaylor (320): numerical angles from integrating the SpinTaylorT4 precession equations, continued analytically through merger and ringdown.

Like LALSimulation, the code changes method without telling the caller:

  • 320 uses the NNLO angles when the in-plane spins are below 1e-7.
  • 320 uses MSA when the SpinTaylor integration cannot be used. This happens when the backward integration is shorter than one coarse step, or when the PN solution starts above fmin. In the random draws it hits about half of the binaries above 150 M☉.
  • MSA uses NNLO when the MSA system cannot be initialised.

One default differs. In lalsimulation 6.2.0, IMRPhenomXP and XPHM default to PhenomXPrecVersion 300, which resolves to the MSA angles (223). The crate defaults to 320, which is what was asked for. Pass PrecessionVersion::Msa to get LAL's default.

IMRPhenomXPHM with SpinTaylor angles

Usage:

use waveformrs::imrphenomx::{IMRPhenomXPHM, PrecessingBinary, PrecessionVersion};

let binary = PrecessingBinary {
    mass_1: 40.0, mass_2: 20.0,                 // solar masses
    spin_1: [0.4, -0.3, 0.2], spin_2: [0.1, 0.5, -0.3],  // at f_ref, L along z
    luminosity_distance: 400.0,                 // Mpc
    inclination: 0.4, phi_ref: 0.1, f_ref: 20.0,
};
let model = IMRPhenomXPHM::with_version(&binary, PrecessionVersion::SpinTaylor)?;
let (h_plus, h_cross) = model.polarizations(&frequencies)?;           // like ChooseFDWaveformSequence
let (h_plus, h_cross) = model.polarizations_uniform(0.25, 20.0, 1024.0)?; // like ChooseFDWaveform (no multibanding)

A call runs these steps in order, each a port of the LAL routine named:

  1. Waveform and precession set-upThe masses and spins are ordered as LAL orders them. The code then builds the aligned-spin waveform variables from the L-frame spin components and computes the precession quantities: χp, the J frame and the angle θJN, the polarisation rotation ζ, and spherical harmonics up to ℓ = 4 (IMRPhenomXGetAndSetPrecessionVariables). XPHM uses m′min = 1 and m′max = 4, so the angles must cover Mf′ = 2Mf/m′ down to (fmin − 0.5 Hz)·2/4.
  2. SpinTaylorT4 evolutionThe orbit-averaged precession equations are integrated backwards and forwards from fref on a coarse grid, then on a fine grid at high frequency. The integrator is the GSL RKF45 adaptive driver as LAL uses it, with Hermite resampling to the output step (IMRPhenomX_InspiralAngles_SpinTaylor).
  3. α and cos β splines, remnant spinL̂ and the spins are transformed to the J frame. α (unwrapped) and cos β are splined against Mf with GSL-identical natural cubic splines. The precessing final spin is computed from the spins at the end of the integration (PhenomXPFinalSpinMod 4), which also updates fRING and fDAMP of the co-precessing modes.
  4. Merger–ringdown continuationAnalytic forms for α and β are matched to the splines at the end of the PN solution and continued through merger and ringdown (alphaMRD_coeff, betaMRD_coeff).
  5. γ from the minimal-rotation conditiondγ/df = −cos β dα/df is integrated with Boole's rule on a uniform grid. Its spline is evaluated up to max(Mfmax, fRING + 4 fDAMP)·2/m′min, and the values at the transition frequency are stored (IMRPhenomX_Initialize_Euler_Angles).
  6. Angles per modeFor each m′ ∈ {1, 2, 3, 4}, α, cos β and γ are evaluated at Mf′ = 2Mf/m′, falling back to the MRD forms beyond the splines. The ε = −γ phase and the Wigner half-angle powers are computed once per m′ and frequency.
  7. Co-precessing modesThe (2,2) mode comes from IMRPhenomXAS and the others from IMRPhenomXHM (IMRPhenomXHMGenerateFDOneMode), with the precession-modified final spin and reference phase. When q = 1 with equal aligned spins, the odd-m′ modes are skipped, as in LAL.
  8. Twist-up and polarisation rotationEach mode is rotated into the inertial frame with the Wigner d-matrices for ℓ = 2, 3, 4 and summed into h+ and h× (IMRPhenomXPHMTwistUp). The result is then rotated by 2ζ.

Validation

The XPHM tests cover:

  • the SpinTaylor, NNLO and MSA versions;
  • uniform grids;
  • restricted mode arrays;
  • eight heavy binaries confirmed to make LAL fall back from SpinTaylor to MSA.

Every suite agrees with LAL to ≤ 7e-16 relative error. In the random draws all 200 binaries per version are compared directly; the results are in the accuracy table. The intermediate quantities (PN solution, splines, J frame, final spin, MRD coefficients, γ) were also compared bit for bit, using a small C harness linked against liblalsimulation's internal functions during development.

NRSur7dq4

NRSur7dq4 (Varma et al. 2019, arXiv:1905.09300) is a time-domain surrogate for numerical-relativity simulations of generically precessing binary black holes. It is trained for q ≤ 4 and |χ| ≤ 0.8, and can be used up to q = 6 and |χ| = 1. It includes the modes ℓ ≤ 4 and covers about 4300 M before merger. The port reproduces XLALSimInspiralPrecessingNRSurPolarizations (as called by SimInspiralChooseTDWaveform), XLALSimInspiralPrecessingNRSurModes (as called by SimInspiralChooseTDModes) and XLALPrecessingNRSurDynamics bit for bit on this platform, and runs 5.2× faster.

Data

  • The file LAL needs. lalsimulation 6.2.0 reads NRSur7dq4_v1.0.h5 (17.5 MB, Zenodo 10.5281/zenodo.14999310, md5 ec4a0a9c6af39ad14dc91d42957144e9).
  • Older copies. Files named NRSur7dq4.h5, from lalsuite-extra or gwsurrogate, contain identical datasets. They lack the CANONICAL_FILE_BASENAME attribute that LALSuite ≥ 7.25 checks, so LAL rejects them; the Rust reader accepts both.
  • Where the file comes from. The crate doesn't ship the file. It finds it through NRSUR7DQ4_DATA or LAL_DATA_PATH, and the tests skip when it is absent. Here it lives in the git-ignored lal_data/ directory.

Reading HDF5 without a C library

The surrogate file uses only the oldest HDF5 features:

  • a version-0 superblock and version-1 object headers;
  • symbol-table groups (version-1 B-trees, symbol nodes and local heaps);
  • 4776 contiguous, uncompressed float64 and int64 datasets.

src/hdf5.rs (912 lines) reads exactly that subset, and returns Hdf5Error::Unsupported for anything else. Every dataset matches h5py in shape, type and a 64-bit checksum. Loading the surrogate takes 7.99 ms; LAL's first call, which loads the data, takes about 80 ms. This avoids linking the C HDF5 library or adding a dependency, at the cost of not reading general HDF5 files.

The evaluation

  1. FitsEvery data piece is a polynomial in (log q, χ1x, χ1y, χ̂, χ2x, χ2y, χa). LAL rebuilds the effective spins, log q and a 22-entry power table for every fit. Here they are computed once per parameter point and shared by all fits at a node; factors of order zero are dropped, which is exact. The sums keep LAL's order of operations.
  2. DynamicsThe orbital phase, the quaternion of the coprecessing frame and both spins are integrated from the reference time over the surrogate's time nodes. As in LAL, the integration starts with RK4 using the half nodes and then switches to fourth-order Adams–Bashforth.
  3. Coorbital modesFits are evaluated at the empirical-interpolation nodes from the dynamics interpolated there, then multiplied by the basis matrix. The basis product uses OpenBLAS's fused dgemv ordering.
  4. FramesThe modes are rotated from the coorbital frame to the coprecessing frame by the orbital phase, then to the inertial frame by Wigner D-matrices built from the quaternions. Pairs of values are computed together in NEON registers.
  5. OutputThe result is resampled onto the uniform output grid with GSL-identical cubic splines and summed into h+ and h× with −2Yℓm. The epoch is rounded to nanoseconds, and labels are switched when m1 < m2, both as LAL does.

Matching LAL bit for bit took four things:

  • the arm64 fused multiply-adds;
  • the GSL spline and divided-difference routines, ported operation by operation;
  • OpenBLAS's order of summation;
  • Darwin's __sincos_stret, which clang substitutes where LAL calls sin and cos of the same angle. These sites were confirmed in the disassembly of liblalsimulation.

Accuracy and speed

The reference tests compare 19 polarization cases from ChooseTDWaveform, plus 6 cases where LAL raises an error. They cover:

  • q from 1 to 6, with q = 7 under unlimited extrapolation;
  • spins up to 0.99;
  • fref ≠ fmin, fmin = 0, and m1 < m2;
  • restricted mode arrays.

They also compare all modes from ChooseTDModes, the dynamics, and 3612 spin-weighted harmonics. Every comparison is bit-identical, with matching epochs and lengths. So are all 200 random draws: q ∈ [1, 6], |χ| ≤ 0.99, M ∈ [20, 300] M☉, sampling at 1–8 kHz.

Issues found in LALSimulation

OpenMP data race in IMRPhenomXP (MSA and PNR angles)

IMRPhenomXPGenerateFD evaluates the waveform in a #pragma omp parallel for loop (LALSimIMRPhenomX.c:2281 on master). IMRPhenomX_Return_phi_zeta_costhetaL_MSA writes the per-frequency spin roots and spin magnitude into the shared pPrec struct (LALSimIMRPhenomX_precession.c:2262–2273) and then reads them back; the PNR angles are passed through pPrec in the same way. With more than one thread, some frequencies are computed with another frequency's values. Results:

  • Default IMRPhenomXP (300, which resolves to MSA): differences of 4–8% of the peak amplitude between runs.
  • 320 falling back to MSA: 14–21%.
  • PNR angles: errors of order one.
  • NNLO (102), SpinTaylor (320) and IMRPhenomXPHM: unaffected.

Single-threaded output is correct and reproducible. The bug is still present on lalsuite master (ba91eb79ca). The full report, with a reproducer and the lines to change, is report/lalsimulation-openmp-race.md (with a PDF copy), and the reproducer script is scripts/reproduce_lal_openmp_race.py.

Smaller findings

  • Error state left set after a successful fallback. When the SpinTaylor integration fails through XLAL_ERROR, the C drivers fall back to MSA and return a valid waveform, but xlalErrno stays set. The Python bindings then raise "Internal function call failed" for a call that succeeded.
  • Hidden global initialisation. XLALSimIMRPhenomXPSpinTaylorAngles reads the global powers_of_lalpi, which only the waveform drivers initialise. Called first in a fresh process, its 3PN orbital angular momentum misses the π² term, and the angles are off by ~1e-3.
  • Ill-conditioned (3,2) set-up. The IMRPhenomXHM (3,2) intermediate phase is fixed by a finite-difference second derivative with step 1e-7. Moving the inputs by 1e-15 changes LAL's own (3,2) mode by up to 3e-3 and the polarizations by ~6e-5, a mismatch of ~2e-9.
  • Results depend on the platform. LAL's arithmetic depends on how the compiler contracts multiply-adds, so SpinTaylor-based results differ between arm64 and x86-64 builds at about the 1e-7 level. This is expected from the analysis in section 4 but was not measured on x86-64.

API review and suggested changes

All work so far kept the existing API: the Waveform trait and the constructors and fields of TaylorF2 and IMRPhenomD are unchanged, and new behaviour comes through additive builders and new types. These changes would make the crate more consistent, and in several cases faster:

  1. One meaning for phi_c. TaylorF2 treats phi_c as the orbital phase and subtracts 2φc. IMRPhenomD and IMRPhenomXAS treat it as the GW phase, so matching LAL's phi_ref needs phi_c = 2 phi_ref. The precessing models take phi_ref directly. Using the orbital reference phase everywhere, as LAL does, would remove a common source of factor-of-two errors.
  2. Private fields and consistent units. total_mass, luminosity_distance and phasing are public and mutable. The distance is passed in Mpc but stored in metres. Because a caller can change these at any time, the models can't safely cache anything that depends on them, so the evaluators rebuild a snapshot on every call. Private fields with builder methods would allow caching, and would make it impossible to change the mass without updating the phasing.
  3. Constructors that return errors. IMRPhenomXAS::new and IMRPhenomXHM::new panic on invalid input, while from_components and the precessing models return Result. TaylorF2 and IMRPhenomD don't check their input at all. One error type and fallible constructors throughout would suit samplers, which must reject parameters rather than abort.
  4. One polarization interface. The aligned-spin models go through Waveform::waveform_modes(f, phi_c, theta_jn). IMRPhenomXHM has polarizations(f, phi_ref, inclination), and IMRPhenomXP/XPHM take everything in PrecessingBinary. A shared trait, with all parameters (including fref, φref and ι) fixed at construction, would make the models interchangeable. It would also let each model precompute things that depend on the extrinsic parameters, such as spherical harmonics and reference-phase offsets.
  5. Caller-owned buffers (now added). The grid methods of section 7 write into buffers the caller owns, and NRSur7dq4 takes a reusable workspace. The original methods still allocate their output; a breaking change could make the buffer versions the main interface.
  6. Separating set-up from evaluation. As in LAL, the SpinTaylor angles depend on the frequency grid through fmin, and fref = 0 means "the first frequency". Taking fmin explicitly would let the integration and splines be computed once and reused across grids. This matters for heterodyned or relative-binning likelihoods and ROQ bases, which evaluate one binary on several grids.
  7. Uniform grids and multibanding. LAL's default multibanding makes IMRPhenomXHM and XPHM 1.1–1.7× faster on uniform grids, at a controlled loss of accuracy. A uniform-grid entry point already exists for XP and XPHM (polarizations_uniform). Porting multibanding would make it the fast path for full-band analyses.
  8. Optional parallelism. Apart from the SpinTaylor integration and the γ integral, every per-frequency loop is independent. A rayon feature, comparable to LAL's OpenMP but without the shared state, would speed up long single waveforms almost linearly. The default single-threaded behaviour would stay deterministic.
  9. Precession default. Document the difference from LAL's default (MSA), or offer PrecessionVersion::LalDefault.

Limitations and future work

  • Multibanding is not implemented. Rust reproduces LALSimulation with PhenomXHMThresholdMband = PhenomXPHMThresholdMband = 0. Comparisons with LAL's defaults on uniform grids will differ at the level of the multibanding tolerance.
  • Only the default model versions are ported. Other PhenomXPrecVersion values (101, 103, 104, 220–222, 224, the PNR and antisymmetric options) and the NRTidal variants are not ported. For the MSA family, 222 differs from 223 only by raising an error instead of falling back to NNLO; 220, 221 and 224 use different expressions.
  • Only one platform was tested. Bit-for-bit agreement was verified on arm64 macOS against conda-forge builds. The x86-64 path of the FMA helpers is based on how those builds are compiled and has not been run. If it differs, the SpinTaylor-based tests at 1e-9 may need platform-specific tolerances or reference data.
  • Only one LAL version was tested. All reference data comes from lalsimulation 6.2.0. Future LAL changes would show up as test failures, which is intended.
  • Grid paths are not bit-exact. The *_on_grid methods agree with LALSimulation and with the per-frequency paths to about 1e-13, not bit for bit, because products of stored powers are rounded differently from direct powers. Use the per-frequency methods where bit-for-bit agreement matters.
  • NRSur7dq4 extras. The polarisation rotation by longAscNodes isn't exposed; it is zero in the default ChooseTDWaveform call. NRSur7dq2 isn't ported, but the data layer is versioned to allow it. The HDF5 reader only handles the subset that the surrogate files use.
  • MSA speed. The MSA angles are only 1.4–1.8× faster than LAL, because the ported elliptic functions dominate.
